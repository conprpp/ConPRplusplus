One layout across three sites

Hall, Office, and Quad follow the same structure. Each site has one Calibration/ directory shared by all of its sessions.

Session folders use the local collection date in YYMMDD format. Identify a session by both its site and date: for example, Hall/260905/.

Session metadata

sessions.csv lists the ISO collection date, day/night condition, duration, sensor and GT counts, and image dimensions. Collection dates use Asia/Seoul time.

duration_s is the interval between the first and last released LiDAR message timestamps.

Timestamps & event index

Filenames and CSV records retain their original integer nanosecond timestamps. They are not rebased to the start of a session. No sensor clock offset is applied to the released timestamps.

stamps.csv

timestamp_ns,sensor
1788594404092761993,cam
1788594404098888397,livox

Events are ordered by timestamp, then by sensor name for ties. GT poses are stored separately and are not included in this index.

cam
The timestamp-named PNG in Camera/.
livox
The timestamp-named BIN in LiDAR/.
imu
The row with the corresponding timestamp in IMU/imu.csv.

A playback index, not a list of synchronized pairs. Camera and LiDAR streams have independent timestamps and sample counts. Equal row numbers do not imply simultaneous observations. The benchmark pairing rule is applied separately.

Sensor files

LiDAR

LiDAR/<time_ns>.bin

Each BIN contains one original Livox Mid-70 message at a nominal 10 Hz. Coordinates are in metres in the LiDAR frame, with +x pointing forward. Retained scans are provided without deskewing, accumulation, gravity alignment, range cropping, or point reordering.

Each point is a 19-byte packed, little-endian record, with no file header or alignment padding.

LiDAR point record: 19 bytes, little-endian
Byte offsetFieldTypeMeaning
0xfloat32x coordinate (m)
4yfloat32y coordinate (m)
8zfloat32z coordinate (m)
12reflectivityuint8Original Livox reflectivity
13taguint8Original Livox tag
14lineuint8Original Livox line
15offset_time_nsuint32Point time offset (ns)

This is not a float32 XYZI layout. Use the packed field definitions below when reading BIN files. In C++, verify the record size rather than assuming a native structure occupies 19 bytes.

point_timestamp_ns = message_timestamp_ns + offset_time_ns

The filename gives the message timestamp, treated as a scan-start time in processing. Keep timestamps as integers to preserve nanosecond precision.

Point-time convention

The addition above defines the dataset's point-time interpretation. It does not independently certify the hardware timestamp origin or camera exposure timing. The nominal recording rate is a guide; use recorded timestamps for timing.

RGB camera

Camera/<time_ns>.png

Images are timestamp-named PNG files from the RealSense D435i. Faces and licence plates are mosaicked; image dimensions and timestamps are preserved.

Images are not geometrically rectified for release. Use the site's camera model when rectification is needed. Libraries such as OpenCV may expose decoded pixels in BGR order.

IMU

IMU/imu.csv

The IMU stream retains the recorded measurements and timestamps at a nominal 250 Hz. The CSV includes a header:

timestamp_ns,qx,qy,qz,qw,wx,wy,wz,ax,ay,az
qx,qy,qz,qw
Recorded IMU orientation, in x,y,z,w order.
wx,wy,wz
Angular velocity in rad/s.
ax,ay,az
Acceleration in m/s², with the gravity contribution retained.

The recorded orientation is distinct from the optimized GT orientation and is not a direct transform to the site's world frame. No additional axis conversion, bias correction, or timestamp shift is applied during release.

Ground-truth poses

GT_pose/poses.csv contains IMU poses only, expressed as T_world_imu. Each row maps IMU coordinates to the site's world frame.

timestamp_ns,x,y,z,qx,qy,qz,qw

Position & orientation

Position is in metres. Unit quaternions use x,y,z,w order. All sessions at a site share a world frame anchored to the first valid IMU pose of its first session: Hall 260905, Office 230531, and Quad 260917.

The three sites have independent world frames. Rotations used to display paper figures are not applied to the released poses or sensor data.

Trajectory timestamps

Rows are selected native scan-end samples. They are not poses at every raw IMU observation or at each LiDAR filename timestamp.

For intermediate times, interpolate position and use quaternion SLERP within supported intervals. Do not extrapolate beyond GT support. Sensor streams can extend outside the GT interval.

These optimized reference trajectories are estimated poses. See pose generation and geometric validation for the method and its validation scope.

Calibration & coordinate frames

Camera intrinsics were calibrated using a checkerboard pattern. Extrinsic calibration was based on LI-Init and Kalibr.

Each site's Calibration/ applies to all its sessions. Hall and Quad share calibration values; Office uses its own camera profile and extrinsics.

Camera model

camera.yaml follows a ROS CameraInfo-style schema: image dimensions, camera matrix K, distortion model and coefficients, rectification matrix R, and projection matrix P.

Extrinsic transforms

extrinsics.yaml contains two homogeneous 4 × 4 matrices. Use homogeneous column vectors and translations in metres. Camera optical axes point right, down, and forward.

LiDAR → IMUp_imu = T_imu_lidar @ p_lidar
LiDAR → camerap_camera = T_camera_lidar @ p_lidar
IMU → cameraT_camera_imu = T_camera_lidar @ inverse(T_imu_lidar)
LiDAR → world, at a supported pose timeT_world_lidar = T_world_imu @ T_imu_lidar

Spatial calibration specifies coordinate relationships; it does not imply that camera and LiDAR observations were recorded at exactly the same instant.

Reading examples

Minimal Python examples for the released file formats. Replace the session and filename with the data you want to read.

Read a LiDAR scan with NumPy 
from pathlib import Path
import numpy as np

point_dtype = np.dtype([
    ("x", "<f4"), ("y", "<f4"), ("z", "<f4"),
    ("reflectivity", "u1"), ("tag", "u1"), ("line", "u1"),
    ("offset_time_ns", "<u4"),
], align=False)
assert point_dtype.itemsize == 19

scan_path = Path("ConPRplusplus/Hall/260905/LiDAR/1788594404098888397.bin")
if scan_path.stat().st_size % point_dtype.itemsize:
    raise ValueError("File size is not a multiple of 19 bytes")

points = np.fromfile(scan_path, dtype=point_dtype)
xyz = np.column_stack([points["x"], points["y"], points["z"]])
message_ns = np.uint64(int(scan_path.stem))
point_ns = message_ns + points["offset_time_ns"].astype(np.uint64)
Read CSV records without losing timestamp precision 
import csv
from pathlib import Path

session = Path("ConPRplusplus/Hall/260905")
with (session / "stamps.csv").open(newline="") as f:
    events = [(int(r["timestamp_ns"]), r["sensor"])
              for r in csv.DictReader(f)]

with (session / "GT_pose/poses.csv").open(newline="") as f:
    poses = [
        (int(r["timestamp_ns"]),
         [float(r[k]) for k in ("x", "y", "z")],
         [float(r[k]) for k in ("qx", "qy", "qz", "qw")])
        for r in csv.DictReader(f)
    ]

Transform LiDAR coordinates at a GT pose time

This example uses NumPy. Supply the actual T_imu_lidar matrix from the site's calibration. The pose and point coordinates must refer to the same supported time; reading a BIN does not itself deskew a scan.

import numpy as np

def lidar_to_world(xyz, position, quaternion_xyzw, T_imu_lidar):
    q = np.asarray(quaternion_xyzw, dtype=float)
    if q.shape != (4,) or not np.isfinite(q).all() or np.linalg.norm(q) == 0:
        raise ValueError("Expected a finite, nonzero x,y,z,w quaternion")
    x, y, z, w = q / np.linalg.norm(q)
    T_world_imu = np.eye(4)
    T_world_imu[:3, :3] = [
        [1-2*(y*y+z*z), 2*(x*y-z*w), 2*(x*z+y*w)],
        [2*(x*y+z*w), 1-2*(x*x+z*z), 2*(y*z-x*w)],
        [2*(x*z-y*w), 2*(y*z+x*w), 1-2*(x*x+y*y)],
    ]
    T_world_imu[:3, 3] = position
    T_world_lidar = T_world_imu @ np.asarray(T_imu_lidar)
    return xyz @ T_world_lidar[:3, :3].T + T_world_lidar[:3, 3]
